## 不具合と回帰確認

| 不具合と再現手順 | 原因・修正 | 回帰確認 |
| --- | --- | --- |
| AI が2,000文字を超えて答えた相談に追質問する、または共有候補を生成する | 人の入力と AI 履歴を同じ2,000文字で検証していた。人は2,000文字のまま、AI は保存上限と同じ4,000文字まで許可 | `check:ai` の追加ケースが変更前に `AI_INVALID_INPUT`、変更後に成功。4,001文字の拒否も確認 |
| 回答を含む長い相談で、発言数が20を超えた後に共有候補を作成する | ストアが上限を超えた要約入力を渡していた。元の質問と根拠になる回答を保ち、直近の発言を合わせて20件以内にする | Firestore Emulator の24発言ケースが変更前に要約失敗、変更後に成功。低確信の返答は除外、全24発言は保存 |
| 生徒の履歴を開き、詳細の方が直前の一覧より新しいタイミングで取得する | 一覧・詳細の時刻が等しいときしか詳細を使えず、再取得を繰り返した。詳細が新しければ採用 | `check:client`、Playwright の GET 応答順の回帰ケース |
| 相談 A の操作が完了する直前に相談 B を開く。B の詳細が遅れて成功、または 404 になる | A の完了が B の取得も無効化した。更新対象だけを無効化し、現在の相談が 404 なら古い詳細を残さない | Playwright の遅延と 404 の回帰ケース |
| 開発プレビューで長い AI 回答の後に質問する、または回答失敗後に相談／解決してから再試行する | 画面から送る履歴の長さと API 制限が不整合。表示は保持し、送信時に発言とリクエスト容量の上限内で直近を使う。相談・解決後の再試行は無効 | プレビューのモック9件。4,001文字の表示保持と追質問、日本語のバイト上限、解決後／教員待ちの拒否 |
| 実モデルに出題範囲・配点を尋ねると、引き継ぐ一方で教員の案内時期を推測した | 根拠不足時に引き継ぎを説明し、未確認の教員案内を約束・推測しないよう指示を追加 | 実モデルで同じ質問を1回再実行。断定・予告は消えたが、本文の引き継ぎ明示は一部未達。画面の状態文言は別に表示 |

## 残課題と提出前確認

- アプリの新規相談・追質問は送信中の連打を防ぐが、保存成功直後に通信が切れて手動で再送した場合に、同じ質問を新規として保存できる。通信切断を注入した試験は未実行。再送前に履歴を確認する。
- 壊れた公開 Q&A が同一カテゴリにあると、ストアのスキーマ検証に失敗して検索・AI 回答が止まり得る。壊れた講義サマリーが混ざると講義一覧にも影響し得る。コードで確認した条件で、実データへの書き込みや破損再現はしていない。壊れたデータを無視するか、利用者へ知らせて管理者の修復を待つかは要確認。
- [Firebase の Emulator と実 Firestore の差](https://firebase.google.com/docs/emulator-suite/connect_firestore#how_the_cloud_firestore_emulator_differs_from_production) により、複合インデックスの稼働確認は本番環境で別途必要。提出に使う公開 URL で Google ログインと招待・質問・教員返信・公開を、チームが許可したデモ講義で一度確認する。
- 実際の公開コミット、Vertex のモデル・ロケーション、Firebase アプリ紐付けと認証の承認済みドメインを確認する。旧資料にある `gemini-2.5-flash` の終了日は公式表で 2026-10-20。公開環境に旧モデルが残っていれば、対応モデルを選定して疎通確認する。提出書類のモデル表記を公開設定とそろえ、生成した候補の個人情報・誤答を教員が確認する。[Google Cloud のモデル提供終了日](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/model-versions)

成功は記載の条件で期待どおり動作したことを示す。すべての環境で不具合がないことを保証する結果ではない。
